# HARM - Delta X Basketball Robot Mainboard

**HARM** is the high-performance motor control and sensor interface motherboard designed for a basketball-playing robot used in the **Delta X** robotics competition.

This board acts as the "lower-level brain," handling real-time motor control, encoder feedback, and actuation. It communicates with an **Intel NUC** (the high-level "brain") via USB, receiving velocity vectors/throwing commands and sending back odometry and status data.

## System Overview

* **Central Processor:** STM32G441KB (ARM Cortex-M4 with FPU).
* **Role:**
    * Receives movement commands (Velocity X, Y, Rotation) from Intel NUC.
    * Computes kinematics for the omni-directional chassis.
    * Executes PID control loops using high-resolution encoder feedback.
    * Controls the ball throwing mechanism.
* **Communication:** USB 2.0 (Virtual COM Port) to Intel NUC.

## Interfaces & Pinout

### **Power Input (J1/J4)**
* **Voltage:** 16V Nominal (4S LiPo Battery).
* **Protection:** Active Reverse Polarity Protection (P-Channel MOSFET).

### **Motor Outputs (J8, J9, J12)**
High-current outputs for the chassis motors (likely 3-wheel Omni or Mecanum configuration).
* **Driver:** TI DRV8243 H-Bridge.
* **Control:** Hardwired PWM + Direction control from MCU.

### **Encoder Inputs (J3, J11, J14)**
Feedback interface for motor quadrature encoders.
* **Signals:** Channel A, Channel B, 5V, GND.
* **Processing:** Signals are passed through **MAX1493x** isolators to protect the MCU from voltage spikes and noise generated by the motors.

### **Thrower Interface (J2)**
Control signal for the ball launching mechanism.
* **Signal:** `THR_PWM_HV` (High Voltage logic PWM).
* **Usage:** Connects to an external high-power Motor Driver or ESC (Electronic Speed Controller) for the flywheel motor.

### **Communication (J5 - USB)**
* **Type:** USB Micro-B.
* **Function:** Data link to Intel NUC.
* **Protocol:** USB CDC (Serial). Sends Binary packets containing target velocities and returns current odometry.

## Power Architecture

The board features a robust power management system designed to prevent "brownouts" during high-current motor stalls:

1.  **Main Rail (+16V):** Directly powers the Motor Drivers (DRV8243). Features massive bulk capacitance banks (C4-C9, C14-C19, etc.) to absorb inductive kickback.
2.  **Intermediate Rail (+5_HV):** Generated by **U8** (LDO). Powers the "High Voltage" side of the isolators and encoders.
3.  **Logic Rail (+3V3):** Generated by **U4** (NCP164). Powers the STM32 MCU and the "Low Voltage" side of the isolators.
4.  **Isolation:** The **MAX14930** chips create a barrier between the noisy 16V/5V motor environment and the sensitive 3.3V MCU logic, ensuring the robot doesn't crash when motors accelerate hard.

## Firmware Context

The STM32G4 firmware is responsible for:
1.  **Kinematics:** Converting robot velocity ($V_x, V_y, \omega$) into individual wheel speeds.
2.  **PID Control:** Maintaining precise wheel RPM using encoder feedback.
3.  **Safety:** Monitoring motor fault flags (`nFAULT` pins from DRV8243) to detect stalls or overheating.
4.  **Thrower Logic:** Ramping up the thrower motor to specific speeds based on distance data from the NUC.
